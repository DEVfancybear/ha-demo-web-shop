### A1 — Lượt bị ngắt giữa chừng (nặng nhất về mặt quy trình)

Thông báo: `the turn was interrupted before this call returned`. Đếm được ≥8 lần, ở các chỗ: `ask_user`,
`write_file src/types/index.ts`, `write_file search-bar.tsx` (2 lần), `edit_file compare-store.ts`,
`edit_file tests/e2e.cjs`, cell `read_file + ipython`, cell `h_dev.kill() + h_build`.

Hệ quả nguy hiểm nhất: một lần `write_file` bị ngắt, lần đọc sau thấy file vẫn là bản cũ (31 dòng) — nếu tin
vào "đã ghi" thì đã mất code. Cách xử lý đã dùng: **coi mọi cell bị ngắt là trạng thái không xác định** — đọc lại
file (hash) rồi mới ghi tiếp; tách việc thành cell nhỏ để lần sau dễ chạy lại.

### A2 — Chữ ký `bash()` khác kỳ vọng

```
TypeError: bash() got an unexpected keyword argument 'timeout_ms'   (2 lần)
TypeError: bash() got an unexpected keyword argument 'env'          (1 lần, tái hiện khi viết log này)
```

Chữ ký thật: `bash(command: str) -> BashHandle`. Cách xử lý: đặt biến môi trường qua `os.environ[...]`
(kernel truyền xuống các lệnh bash sau) và tự viết vòng chờ trong Python.

### A3 — `kill()` để lại tiến trình con

Sau `h_dev.kill()`, `netstat` vẫn cho thấy:

```
TCP    0.0.0.0:3210   0.0.0.0:0   LISTENING   14988
```

Đầu phiên viết log này còn một server `next start` sót (PID 12472, cha 12400) vẫn giữ cổng 3210. Tác động kép:
(1) cổng bị chiếm, (2) file `.tmp/*.db` bị khoá (A5), (3) nguy cơ `next build` ghi đè `.next` của dev đang chạy.
Cách xử lý: sau mỗi lần kill phải kiểm tra cổng, và diệt theo PID bằng
`powershell -NoProfile -Command "Stop-Process -Id <pid> -Force"`.
Lần chạy lại trong log này thì `kill()` sạch (cổng trống ngay) — nên đây là lỗi **không ổn định**, càng phải kiểm tra.

### A4 — `taskkill` qua Git Bash

```
ERROR: Invalid argument/option - 'C:/Program Files/Git/PID'.
```

Git Bash biến `/PID` thành đường dẫn Windows. `MSYS_NO_PATHCONV=1 cmd //c "taskkill /PID ... /T /F"` chỉ in banner
mà không diệt được. Cách đúng đã dùng: PowerShell `Stop-Process`.

### A5 — File DB bị khoá

```
PermissionError: [WinError 32] The process cannot access the file because it is being used by another process: '.tmp/e2e-shop.db'
```

Cách xử lý: diệt server giữ file trước, rồi mới xoá. Ở lần chạy lại trong log này đã xoá 6 file `.tmp/*.db`
không lỗi nào, đúng thứ tự đó.

### A6 — Thông báo hoàn thành nền không được chấp nhận

```
[background output (unattributed)] Background bash completion follow-up for pid X was not accepted.
Inspect the saved handle with poll(), output(), or tail().
```

Hơn 12 lần, ví dụ pid 16664, 4488, 14924, 3016, 17688, và 2 lần mới (17268, 22704) ngay khi viết log này.
Cách xử lý: bỏ qua thông báo, chủ động `poll()`/`output()` trong vòng lặp Python.

### A7 — Không tự tạo thư mục cha

`FileNotFoundError` khi ghi `src\components\seo\json-ld.tsx` và `src\app\api\products\[slug]\reviews\route.ts`.
Cách xử lý: `os.makedirs(os.path.dirname(p), exist_ok=True)` trước khi ghi.

### A8 — Mất biến kernel sau khi ngắt

`NameError: name 'route_vouchers' is not defined` và `NameError: name 'sitemap' is not defined` — biến được tạo ở
cell bị ngắt nên cell sau không có. Cách xử lý: khai báo lại biến ngay trong cell dùng nó; không dựa vào biến
sống qua ranh giới lượt.

### A9 — Kernel revive

```
[python-state-restored] Your Python kernel state was revived from your previous session...
These could not be restored and must be recreated if needed: agent_message, agent_observe, goal, rlm_heartbeat
```

Cách xử lý: `import` lại skill khi cần; `rlm` vẫn còn.

### A10 — `rlm.list_subagents()`

`err rlm.list_subagents entry has invalid activity kind`. Cách xử lý: dựa vào thông báo `[child-exited ...]`
và `rlm.collect(...)`.

### A11 — `attach_image`

Hai lỗi khác nhau:
1. `TypeError: run() got an unexpected keyword argument 'path'` — chữ ký thật là `run(*paths)`.
2. `RuntimeError: deepseek-v4.1-flash does not support vision` — model không có vision.

Cách xử lý: truyền đường dẫn theo vị trí; và kiểm tra ảnh OG bằng số đo thay vì bằng mắt
(magic bytes `89 50 4E 47`, `content-type: image/png`, số byte, log font fallback của `next/og`).

### A12 — Con "no-reply" bị cắt 8000 ký tự

```
[child-exited: no-reply child:p3-autocomplete-audit] ... [answer cut at 8000 characters]
```

Con đã chạy xong nhưng câu trả lời dài không được gửi thành message, chỉ còn bản cắt 8000 ký tự. Cách xử lý:
yêu cầu con ghi kết quả ra file trong `session_dir` rồi trả về đường dẫn; hoặc hỏi lại theo phần nhỏ.

### A13 — `urllib` khác `curl`/`node`

`ConnectionResetError` khi GET `/robots.txt` ngay sau khi start server; `TimeoutError` khi tải ảnh OG trong khi
`curl`/`node` lấy `200 image/png` trong 356ms. Cách xử lý: hàm `req()` có retry + vòng chờ server sẵn sàng;
khi nghi ngờ thì đối chiếu bằng 2 công cụ khác nhau trước khi kết luận "server lỗi".

### A14 — Không có browser kèm theo

`require('playwright')` không có trong `node_modules`; `browserType.launch` báo
`Executable doesn't exist at ...chromium_headless_shell...`. Cách xử lý: dùng `playwright-core` + `channel: 'msedge'`
(Edge có sẵn trên máy) — đúng cách `tests/e2e.cjs` đang chạy.

### A15 — Cảnh báo build (mức dự án, không phải lỗi ha)

Khi chạy `npm run build` trong lúc viết log này, Turbopack cảnh báo `fs.statSync(...)` với đường dẫn không tĩnh
trong `src/lib/db.ts` (import traces: `src/lib/stock.ts`, `src/app/api/products/[slug]/route.ts`,
`src/app/products/[slug]/page.tsx`, `src/lib/reviews.ts`) → Next kéo cả project vào bundle server. Build vẫn PASS.
Đề xuất: thêm `/*turbopackIgnore: true*/` hoặc cố định đường dẫn DB.

## D. Đề xuất sửa ở hạ tầng (theo mức ưu tiên)

1. `kill()` phải diệt cả cây tiến trình trên Windows, hoặc trả về PID con để người dùng tự diệt.
2. `bash()` nên nhận `timeout_ms`/`env` (hoặc docstring nói rõ là không nhận) để tránh `TypeError` khó hiểu.
3. Con "no-reply": lưu nguyên văn câu trả lời vào file trong `session_dir` và báo đường dẫn, thay vì cắt 8000 ký tự.
4. `write_file`/`write_text` tự tạo thư mục cha.
5. `rlm.list_subagents()` chịu được entry lạ.
6. `attach_image` báo trước (hoặc tự bỏ qua) khi model không có vision.
7. Đánh dấu rõ cell bị ngắt theo cách idempotent để chạy lại an toàn.
